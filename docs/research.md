# Mira 研究应用

工作台位于 `/research`，使用 `/admin` 管理令牌登录。单项研究后台使用 `/research/[id]`，当前页签保存在 URL 的 `tab` 参数中，刷新保持研究与页签。发布后通过 `/r/[code]` 的11位随机短码邀请参与；列表中的“分享管理”生成单项研究的管理链接。

## 使用流程

1. 在管理后台配置聊天模型及 Tavily 密钥。
2. 输入想研究的问题，可自由补充相关背景。Agent 按实际信息缺口提出澄清，研究者说明已知事实和仍不确定的安排。
3. 创建请求先保存后台任务，由 DO alarm 执行规划。Agent 自主选择检索词、阅读已发现来源、请求澄清或形成方案，澄清对话和来源持久保存。列表显示生成中、待补充、生成失败、待发布、收集中或已结束；返回列表、重新聚焦和页面停留期间自动刷新，也可手动刷新。失败任务可在准备页重试。
4. 审阅研究问题、方法、题目用途、适用条件、非回答选项、追问安排、预计时长、计分和来源。可直接编辑，也可通过“让助手调整方案”提出自然语言修改要求。修订成功前保留原方案，过程中可恢复原案。发布前确认参与对象、实际数据用途、联系方式、保存期限及已有参与条件。原始研究意图与发布确认事实分别保存。
5. 参与者阅读说明并同意后逐题作答；有参与条件时另外确认。研究默认不设统一年龄门槛。
6. 系统按已发布的前置条件呈现适用题目。方案启用补充追问时，Agent 根据实质回答、信息缺口和参与意愿决定澄清与收尾；预计时长提供节奏参考。
7. 管理者查看统计和导出，点击“结束收集”后自动进入分析页。系统保存该次截止的数据快照并在后台生成文本分析，报告可下载，失败可按原快照重试。保存期限内可“继续收集”，使用原参与链接续答；再次结束会生成新一轮报告。
8. 在生成准备页或研究管理页删除研究。删除收集中研究时先结束收集，清除方案、回答、任务和短码，链接随即失效。生成中的任务可直接取消并删除，晚到结果会被丢弃。

## 方案与数据

每题记录收集用途及可选的维度关联。变量可以承担多个研究用途，数据类型决定作答控件；参与条件用于界定目标人群。方案应说明采集精度、计划分析、偏差与预试。系统支持文字、单选、多选、下拉、评分、滑块和数字。

参与界面以题目、选择和下一步为中心；AI 参与、数据用途、退出方式和实际操作后果在需要知情选择的位置简明说明。措辞直接表达目的，也保留必要的不确定性、拒答选项和出错指引。研究者界面展示审阅所需的方法依据。

公开参与对象使用发起者填写的原文；模型生成的对象范围评估仅展示在研究者的方法区。开场、收尾与题目面向参与者，待确认事项、招募建议和方法限制放在研究者材料中。

展示标题面向参与者，以简短、中性的自然语言描述访谈主题。研究者可在管理页标题旁修改展示标题，发布后也可修改；这个操作只更新标题，保留题目、计分、版本和回答。

预定题目的措辞、选项、量尺和依赖关系在同一发布版本保持一致。方案选择固定或自适应题序，以及末尾或穿插追问；执行层按这些权限行动。`source=core` 表示方案中预定的问题，`source=probe` 表示访谈中生成的追问；这一区分记录题目来源，不决定变量的科学性质。追问用于解释已有信息，完整保留实际题目和衔接语。

Agent 规划题目覆盖范围与时长，根据研究目标决定每题是否提供非回答选项，并说明其测量含义和分析影响。`responsePolicy.options=[]` 表示该题仅显示实质作答控件，参与者仍可随时结束或撤回。非回答选项包含稳定编号、参与者标签、缺失含义和继续/结束路径。

`applicability.all` 用题目回答定义适用条件；全部满足时呈现。固定题序引用前序题，自适应题序可引用其他题；显式 DAG 校验通过拓扑排序检查悬空依赖和环路，只将依赖满足的题交给 Agent 选择。零次经历可作为实质回答控制后续题组。前序条件已知为假记为结构性不适用；前置回答缺失记为资料不足；尚未到达的前序题保持未到达状态。条件引用顺序与比较类型在生成、保存和发布时验证。研究者可在题目详情编辑这些规则，在方案中决定追问是否启用。

正式运行代码使用当前研究契约。一次性升级工具与核验副本保存在本地操作归档中。研究版本、原题及原始回答保持可核对；收集开始后补充的方法规则保留修订时间和原方案，历史未收集的信息保持未知。

## 修改、结束与删除

参与页提供“上一题”，也可从已答内容修改任意答案。独立的预定答案保留；前置回答修改后，重新评估适用条件，失效分支答案存入 JSON 的 invalidatedAnswers，当前统计使用仍然适用的回答。修改预定答案后，旧追问失效并重新判断后续问题；修改追问时保留之前的追问，重算后续追问。统计使用新值，JSON 保留修订前回答及分支失效审计，JSON 和 CSV 保存最后修订时间与题目参考期。租约防止并发回答互相覆盖。

参与者可主动结束，已回答内容保留。撤回回答位于“参与说明”中，删除本次参与记录。研究者删除整项研究是独立的管理操作；确认后清除研究方案、回答、限额记录、任务、索引与分享短码，并取消到期任务。

## 收集分析

每次结束将研究方案、版本、逐题统计和实质文字回答保存为固定快照。文字回答按批次完整处理，合并为主题摘要，再结合确定性统计生成观察结果、解释范围与后续建议；报告标明截止时间、记录数和实质回答数。空数据直接显示资料不足。分析随 JSON 数据导出，也可单独下载文本。已结束但尚无报告的研究可在分析页生成。

继续收集保留题目、版本和原保存期限，旧报告仍对应原截止点。撤回回答或移除记录会清除既有分析及快照；可根据剩余数据重新生成。到期和删除同时清理回答、报告与快照，晚到结果无法恢复已清理的数据。

## 计分与解释

维度默认逐题描述。明确选择探索性均值并提供依据时，关联的评分与滑块题按固定上下界归一化到0–100；反向题先取100减原分，再等权平均。当前实现要求至少两道关联量尺题且均有效作答。这是受支持的计分规则，不能作为维度结构已经成立的证据；其他计分方法需另行实施或导出分析。

主动非回答保存 `value=null` 及选项编号、标签、含义和路径。JSON 和 CSV 区分 `declined`、`unknown`、参与者选择的 `not_applicable`、原因未收集的 `unspecified`；自动分支省略以独立记录区分 `not_applicable`、`prerequisite_missing` 和 `not_reached`。CSV 中主动非回答保留 nonresponse_id，自动省略的该字段为空。逐题统计展示实际回答、主动未答、不适用、前置资料缺失和未到达，有实质回答的记录数与流程结束数分别呈现。进行中的实质回答也进入逐题统计，数量资料按原始值汇总。缺失机制假设与适用分母由研究方案和分析者说明，缺失类型标签仅提供观测信息。默认仅提供样本量、均值、样本标准差和分布。区间估计与检验需按抽样、聚类和缺失机制另行确定。总体推断和因果解释需要研究设计支持。

实际应用需完成目标人群预试、内容与构念效度、信度、必要的测量等值性和样本量规划。方法依据及阅读范围见 [research-evidence.md](./research-evidence.md)。

## 运行边界

以下是应用运行约束，需与研究设计分开评估：

- 单次参与 API 请求最多64 KiB，方案编辑最多512000字节；模型和检索上下文也受供应商容量约束。长回答不再被2000字符阈值截断。
- 规划与访谈使用独立的正向任务说明。系统指令定义职责，研究者输入、文献与参与者回答作为任务数据。规划每轮最多12个模型动作、24个来源；这些是运行资源边界。访谈 schema 根据方案允许核心题选择、穿插澄清或末尾追问，核心题仍待完成时保持相应覆盖。方案校验失败后返回具体字段路径和要求，供一次重新生成。
- 模型输出使用所选模型声明的容量。方案使用最高思考档，访谈使用 `high`。方案生成保留主动取消，访谈调用45秒；访谈超时保留回答，继续预定题或收尾，并在导出中记录 `fallbackCount`。
- 同一地址的按日加盐摘要每项研究每天最多开始5次，作为重复访问保护；共享网络用户可能共用限额。既有参与者续答不重复计数。
- 评分按钮控件支持最多11个等距刻度；更密集的数值范围使用滑块或数字控件。选项唯一、范围有效、回答匹配题目属于数据完整性校验。
- 描述字段仍有协议长度约束，保存期限由研究设置确定。资料摘录与方案校验的限制属于实现能力，不构成研究结论。

## 存储与权限

每项研究使用独立 SQLite Durable Object；Directory 的 research 插件保存管理索引与短码映射。参与凭据使用 HttpOnly、SameSite Cookie；Cookie 保留时可刷新续答及撤回。导出使用独立参与序号，包含题目用途、修订时间和实际呈现内容。

API、研究页、短链接页及 SvelteKit 数据响应均设置 `private/no-store`。全站列表和创建验证管理员身份。单项研究的编辑、发布、结束/续收、分析、删除、统计和导出允许管理员或该项研究的管理凭据。管理链接持有人无需登录即可查看和管理这项研究；链接使用256位随机凭据，打开后交换为 HttpOnly、SameSite Cookie 并跳转到干净的研究地址。凭据在所属研究中校验，删除研究后失效。管理页使用 `no-referrer`。回答先落库，再生成引导；晚到的模型结果不能覆盖已撤回或主动结束的状态。

到期 alarm 清除回答、分析快照、报告与限额摘要，保留研究方案并停止接纳。已导出副本和供应商持有的数据按各自处理流程管理。

## 本地草稿与查询状态

新建研究的主题和背景、未保存的方案编辑、当前题目回答及修改回答，通过 `idb-keyval` 保存到独立的 IndexedDB。管理草稿使用已鉴权身份的专用摘要隔离；方案按研究及当前版本恢复，参与草稿按研究、参与记录、题目和题目内容隔离。关闭标签页后，在同一浏览器和相同身份下重新打开仍可恢复。原 `sessionStorage` 作答草稿首次读取时迁移，完整保留空白与换行。

异步恢复仅填充尚未编辑的字段，输入即时排入写入队列。保存或提交成功后清理对应草稿，结束、撤回和删除时清理相关作用域；清理同时更换记录代际，阻止其他已打开标签页的旧写入恢复已清理内容。方案和新建表单提示已恢复的草稿，并提供“放弃草稿”。浏览器拒绝本地存储时，表单继续使用内存。IndexedDB 保存于当前浏览器，正式方案、回答和报告以服务端为准。

研究列表、单项详情统计、规划进度和分析报告使用官方 `@tanstack/svelte-query` 的 `QueryClientProvider`、`createQuery` 和 `useQueryClient`。相同查询共享进行中的请求，组件卸载时取消无人使用的请求，页面隐藏时暂停轮询，重新聚焦或恢复网络时刷新。规划进入待补充或失败状态、分析完成后停止轮询；统计仅在数据页收集中定时更新。写操作成功后更新或失效对应查询，写请求由明确操作发起。退出研究页或切换管理身份时清理内存查询缓存。

- `src/lib/contracts/research.ts`：方案、题目、回答协议及校验。
- `worker/plugins/research/`：模型、检索、存储、统计、索引与短码。
- `worker/research.ts`：DO RPC、后台生成和到期任务。
- `src/lib/server/features/research.ts`：认证、请求边界和参与凭据。
- `src/lib/plugins/research/`：复用 daisyUI 与 Bits UI 的管理和访谈界面。

状态观察、资料完整度及时间信息的文献与实现见 [research-observation.md](./research-observation.md)，部署影响及性能测量见 [research-deployment.md](./research-deployment.md)。
